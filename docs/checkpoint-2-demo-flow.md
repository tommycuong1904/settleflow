# SettleFlow — Checkpoint 2 Demo Flow

## Goal
Show that SettleFlow already has a credible product direction, visible payout workflow, and clear Arc / USDC alignment.

## Recommended route order

### 1. Landing page
URL: `/`

Talk track:
- SettleFlow is an Arc-native USDC payout workflow for crypto teams.
- It replaces ad hoc wallet transfers with milestone-based, approval-gated payouts.

What to point at:
- Build on Arc / DeFi framing
- Milestone payouts
- Approval-gated release
- Arc-native settlement

### 2. Dashboard
URL: `/dashboard`

Talk track:
- This is the operator view for payout operations.
- It shows active payouts, pending approvals, and released milestones.

What to point at:
- KPI row
- Active payout list
- Pending review queue
- Recent releases with Arc proof snippets

### 3. Payout detail
URL: `/payouts/payout-detail`

Talk track:
- This is the core workflow screen.
- It shows the milestone journey from submitted work to approval to release.

What to point at:
- Summary block
- Released milestone
- Submitted milestone with Approve / Reject controls
- Pending milestone
- Settlement proof block
- Arc Testnet / USDC release target

### 4. Create payout
URL: `/payouts/new`

Talk track:
- This is how a team structures a new contributor payout.
- The payout is defined up front as milestone-based and review-gated.

What to point at:
- contributor selection
- wallet field
- milestone split
- workflow preview

## Best story arc
1. Why this product exists
2. What the operator sees
3. How approval gates release
4. How Arc / USDC shows up in the product
5. How a new payout gets created

## Do not oversell
Be explicit that current release actions are scaffolded / mock-backed for checkpoint purposes, while the Arc payment path is already structurally prepared in the repo.
